# MD 配置与迁移规则

## 人维护的内容

只解析 `company-knowledge-config:v1` 标记之间的两列表格。允许 MdRoot、FilesRoot、重复的 WorkRoot；未知字段、重复目标、相对路径、占位符、错误标记、过大文件会被拒绝。其他 Markdown 内容不执行、不当作指令。配置 MD 自身不作为工作资料归档。

工作目录需要存在并可访问；不允许整盘作为工作范围、符号链接越界、目标相互包含或目标与私有状态位置重叠。真实 MD 应放在仓库外、私有目录内或使用 `*.local.md` 文件名。公开模板不接受直接写入真实路径后安装。

## 程序管理的内容

首次使用默认采用系统当前用户的本地应用数据目录，生成固定配置入口和本机状态根目录。StateDir 可选，只改变运行数据的位置；之后省略参数会保留此前选择。两个客户端通过同一入口共用身份。

状态根目录下的 generations 保存完整的活动状态版本及旧版本。固定入口由程序原子更新，客户端和计划任务不必跟着改地址；旧 JSON 安装升级时沿用原入口，所以不能把整个旧位置当成无用文件随意删除。目录结构及内部 JSON 均无需员工编辑。

## 应用过程

1. 解析 MD，校验路径、客户端注册一致性及私有状态位置。检测到配置表格变化后停止新采集。
2. 持久化迁移计划，暂停新数据操作，等待进行中的操作结束。旧 JSON 服务缺少迁移协议，Windows 升级时只停止指向该配置的旧知识库进程。
3. 创建新的状态版本，复制员工资料、开关、已登记队列和快照。只访问队列明确记录的文件，不读取原始工作文件，不扫描 NAS 历史目录。
4. 目标变化时，对快照校验 SHA-256，使用无覆盖提交复制到新员工目录。同名同内容直接复用；同名不同内容拒绝覆盖。已登记但尚未上传的快照也纳入迁移。
5. 全部完成且 MD 未再次改变后，原子切换固定入口。归档 ID 和员工 ID 保持不变，运行中的新版 MCP/监听器加载新配置并重建监听基线。

旧状态和旧 NAS 文件始终保留，不自动删除。迁移到新目标是有意复制已有归档，不代表再次采集原文件；重试不会在新目标生成额外副本。NAS 副本被手工修改的内容不自动合并，以程序登记的快照为准。

## 工作范围变化

新增工作目录不会触发扫描。移除目录后，不再监听其中的文件；其未上传快照保留为 scope_paused，不自动补传。重新纳入范围后，还需由 Agent 明确处理该文件才恢复该快照。已经存储的历史归档仍保留。

修改 WorkRoot 只修改允许范围，不推断新旧工作文件夹之间的搬家映射。同一路径、同一内容跨客户端去重；不同原始路径不会自动合并，以免把两个不同工作文件混为一份。

## 失败与恢复

复制阶段失败时旧入口不切换，采集保持暂停。已经复制的新文件和新状态版本保留供重试。重复执行相同安装命令会按原计划继续，并校验已有内容；修改为另一份迁移方案前应先取消未提交计划。

入口已提交但客户端注册收尾中断时，重复安装完成收尾，不重新生成员工身份或队列。迁移日志和就绪标记用于辨别这个阶段。取消操作不能回滚已提交入口，不会删除已复制的数据。

这套流程不执行跨 NAS 的物理原子移动，也不删除备份；原子切换的是本机配置入口。需要回收旧数据时，应先核对新位置完整性，再另行明确清理。
