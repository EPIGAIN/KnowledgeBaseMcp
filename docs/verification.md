## 豆包命令字段空格解析修复（2026-11-09）

- 起因：已记录的豆包客户端错误为 `CONNECTOR_STDIO_EXECUTABLE_NOT_FOUND: COMMAND_NOT_FOUND`。豆包把连接器“命令”框按命令行解析，含空格的完整路径（如 Windows 的 Node 安装目录或豆包运行时目录）在第一个空格处被截断，剩余部分被当成参数。本项目不写豆包内部设置，因此修复放在生成的接入资料和安装输出中。
- 安装结果新增 `commandField`（路径含空格时自动加引号，否则与原值相同）、`commandLine`（界面只有一个整行输入框时使用）和 `requiresQuoting`。`doubao-stdio.json` 的 `command`/`args` 仍是未加引号的结构化值，JSON 导入方式不变；PowerShell 与 macOS 安装器据此打印“命令”框和整行命令，并在需要时提示引号原因。
- 新增 Windows 引号边界（空格、内嵌双引号、结尾反斜杠）、POSIX Shell 引号、控制字符拒绝和 POSIX 真实 `/bin/sh -c` 往返测试；安装结果与导出的 JSON 一致性也有回归覆盖。
- 本次 `npm run test:doubao`：10 项通过。完整 `npm test`：74 项通过、3 项跳过；另有 1 项终端观察器用例在当前 Linux/WSL 环境中失败，与本改动无关，改动前复现相同结果。Windows 安装器脚本本轮只做了人工核对，未执行或重新注册计划任务。
- 未连接真实豆包客户端：本轮没有在豆包界面重新保存连接器，也不会替用户修改界面。修复依据是已记录的客户端错误和本机 STDIO 诊断，命令含空格的豆包版本仍需按 [豆包接入说明](doubao.md) 做一次界面验收。
